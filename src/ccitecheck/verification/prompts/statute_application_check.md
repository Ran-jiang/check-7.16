# 法律适用与格式核查

法条为 `statutes`，原文为 `original_text`。请将全部法条与全文放在一起比对，只核查以下五类问题：

1. **法律与事实的关联性**：法条的主体、事项、适用条件和法律后果是否与原文事实相符；没有具体事实支撑时不要臆测。
2. **直接引用改写权威来源**：原文明示直接引用法条时，是否增字、漏字、换词或改写，导致引文不再忠实于权威文本。连续、忠实地节选原文不算错误。
3. **法律适用的逻辑性**：法条能否推出原文的法律结论，适用条件、时间先后或推理关系是否明显矛盾。
4. **法律简称歧义或不一致**：同一简称是否可能指向不同法律文件，或同一法律文件在全文中的简称前后不一致并造成识别歧义。
5. **格式错误**：请查找本篇文章是否存在多字、少字、重复字、错别字的情况。只提示能够指出具体文字位置的问题，不检查文风、语法偏好或排版样式。

法名、文号、效力状态和条款编号由其他模块核查，不在这里重复提示。同一处文字差异只归入一类：偶发的多字、少字、重复字或错别字归为 `format_error`；对法条语句的实质改写归为 `direct_quote_unfaithful`。

示例参考：

- 《劳动法》第四十四条第三项没有“另向”，写成“另向支付不低于工资的百分之三百的工资报酬”改变了法律后果，属于直接引用改写权威来源。
- 称1999年司法解释采用了2018年司法解释的思路，或称2004年文件进一步明确2012年法律，属于时间逻辑倒置。
- 将“教育法”作为简称，可能无法区分《教育法》《义务教育法》《高等教育法》《职业教育法》，属于简称歧义。
- 同一法律文件在全文中使用多个无法对应的简称，或者同一简称前后指向不同文件，属于简称不一致或歧义。

没有发现上述问题时输出 `pass`，不要提示。发现问题也只能输出 `review`，等级固定为“待核查”，不得输出“未通过”、风险等级或确定性结论。只依据输入内容，不凭模型记忆补充法条；依据不足时不要制造问题。

仅输出一个可由 `JSON.parse()` 解析的 JSON 对象：

{"comparison":"不超过100字的比对摘要","verdict":"pass|review","reviews":[],"notes":""}

`pass` 时 `reviews` 必须为空。`review` 时每项格式为：

{"error_type":"rule_fact_mismatch|direct_quote_unfaithful|application_logic_error|legal_alias_inconsistent|format_error","review_level":"待核查","summary":"原文、法条和问题的具体对照","suggestion":"需要人工核查或修改的具体内容","related_sources":["《法名》第X条"]}

所有文本只写面向用户的自然语言，不输出内部标记或 Markdown。
