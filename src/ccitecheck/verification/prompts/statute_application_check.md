# 法律适用与格式核查

法条为 `statutes`，原文为 `original_text`。请将全部法条与全文放在一起比对，只核查以下四类问题：

1. **法律与事实的关联性**：法条的主体、事项、适用条件和法律后果是否与原文事实相符；没有具体事实支撑时不要臆测。
2. **引文不忠实于权威原文**：原文明示直接引用或转述法条时，是否增字、漏字、换词或改写，导致含义偏离权威文本。连续、忠实地节选原文不算错误。权威文本与原文语言不同时，应作跨语言比对，不得仅因语言不同提示问题。
3. **全文法规引用简称不一致**：同一法律文件在全文中的简称前后不一致，或同一简称前后指向不同文件。
4. **格式错误**：请查找本篇文章是否存在多字、少字、重复字、错别字的情况。只提示能够指出具体文字位置的问题，不检查文风、语法偏好或排版样式。

## 核对方法

对原文中每个由法条直接引出或据此推出的结论，逐项建立并比较以下要素：

1. 义务或权利主体；
2. 行为、对象及处理方式；
3. 必要条件、例外和适用范围；
4. “应当、可以、不得、仅限于、免除”等规范强度与法律后果；
5. 数字、期限、否定词及并列关系。

必须先在权威文本内部解析“其、该主体、该义务”等代词的先行词，再与原文替换后的名词逐一比对；原文把代词展开成一个不同于先行词的相关主体，不得视为同义改写。权威文本只是缩小适用范围、减少履行方式或限制义务内容时，不等于完全免除义务；只排除本文件适用时，也不能据此推出其他法律义务一并消灭。只有逐项完成上述核对且全部要素均无实质差异，才可输出 `pass`，不得仅凭两段文字主题相同即判定一致。

允许提示“引文内容与所引规范不对应”，但禁止凭模型记忆补写正确条号，编号纠正只由候选验证链负责。已经明确由错条导致的内容差异，不要再拆成罪名、构成要件、法定刑等多项提示；独立存在的实质改写仍需核查。

法名、文号、效力状态和条款编号由其他模块核查，不在这里重复提示。不得比较 `original_text` 中的法律名称与 `statutes` 中的 `cited_source`、`law_title` 或 `source_metadata`；二者之间的法律名称差异（包括错字、近义字、简称与全称不一致）一律不属于本核查，不得据此输出 `meaning_distorted` 或任何 review；文号、效力状态和条款编号差异同理。只有 `original_text` 内部对同一法规的简称前后不一致，才可输出 `legal_alias_inconsistent`。同一处文字差异只归入一类：偶发的多字、少字、重复字或错别字归为 `format_error`；对法条语句的实质改写归为 `meaning_distorted`。

示例参考：

- 《劳动法》第四十四条第三项没有“另向”，写成“另向支付不低于工资的百分之三百的工资报酬”改变了法律后果，属于引文不忠实于权威原文。
- 同一法律文件在全文中使用多个无法对应的简称，或者同一简称前后指向不同文件，属于全文法规引用简称不一致。
- 把权威文本中的义务主体替换为相关但不同的主体，属于实质改写。
- 把“义务仅限于以某种方式履行”改写成“可以免除该义务”，属于改变规范强度和法律后果。

没有发现上述问题时输出 `pass`，不要提示。发现问题也只能输出 `review`，等级固定为“待核查”，不得输出“未通过”、风险等级或确定性结论。只依据输入内容，不凭模型记忆补充法条；依据不足时不要制造问题。

仅输出一个可由 `JSON.parse()` 解析的 JSON 对象：

{"comparison":"不超过100字的比对摘要","verdict":"pass|review","reviews":[],"notes":""}

`pass` 时 `reviews` 必须为空。`review` 时每项格式为：

{"error_type":"rule_fact_mismatch|meaning_distorted|legal_alias_inconsistent|format_error","review_level":"待核查","summary":"原文、法条和问题的具体对照","suggestion":"需要人工核查或修改的具体内容","related_sources":["《法名》第X条"]}

所有文本只写面向用户的自然语言，不输出内部标记或 Markdown。
